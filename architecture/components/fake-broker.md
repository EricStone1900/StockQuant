# FakeBroker模拟券商组件架构

状态：设计/NOT_RUN。V1.3起覆盖三版全部券商操作，V1.1账户初始化可先使用固定期初数据，不能因此声称已有独立券商对账。配套[执行域](../services/trade-execution-service.md)和[历史回放](../04-historical-replay.md)。

## 1. 定位与代码归属

这是执行服务的外部协议测试边界，可独立进程/容器部署，建议放tests/support/fake-broker与fixtures/broker-events并由Compose测试配置启动。不是新增业务领域，也不是某真实券商的模拟API。精确实现语言/协议映射在V1.3 S0冻结。

独立数据库/User或明确隔离的持久存储拥有模拟券商账户、订单、原始成交、现金/持仓和故障状态；不能读组合账表然后原样返回以伪造对账一致。期初通过版本化Fixture/API初始化。

## 2. 协议端口

| 操作 | 行为 |
|---|---|
| capability/account | 返回版本化订单类型/会话/数量/查询能力及独立资产快照 |
| place | 接收稳定clientOrderId、账户/mode/run和订单内容；按能力/撮合政策接受或拒绝 |
| query/cancel | 查询原订单；撤单有独立接受/确认和竞态，不直接修改执行域状态 |
| fills/reports | 增量或累计回报，稳定externalFillId及原始载荷证据 |
| simulation-control | 仅测试身份设置故障计划/市场step，强制run/目标范围；无真实Broker转发 |

实际HTTP路由和字段由执行ExecutionVenue端口契约生成并测试，不在此捏造已可调用地址。

## 3. 状态与事务

模拟订单接受、brokerOrderId和幂等记录本地持久化；若能力配置不支持clientOrderId幂等，仍允许查询原订单并测试执行域UNKNOWN保护，不承诺任意网络重试安全。

成交由有效订单、版本化市场/撮合模型与资源规则产生，更新独立券商现金/持仓/成交并持久化报告投递记录。报告可重复/迟到，但原成交ID稳定；执行域负责归一化/Outbox，组合域负责自己的一次入账。

历史模型代码归执行域，可作为固定纯规则依赖注入组件；同run只有一个Fill生成器。快照和日线/分钟模型分别标记，不随机制造价格/利润。模拟外部订单/费用更正通过组件原始报告进入同一归一化链路。

## 4. 固定与随机故障

固定场景包括拒单、部分成交、撤单期间成交、撤单拒绝、已接受但响应丢失、查询失败、重复/乱序/迟到报告、累计更正及外部订单。每项可在Web或CLI选择。

随机故障使用seed+计划版本并保存实际发生事件序列；并发调度影响顺序时按记录重放。正常订单仍满足业务因果；故意非法回报另标协议破坏场景，测试执行服务隔离能力。

“接受响应丢失”必须先持久化接受再丢响应；随后查询可恢复同brokerOrderId，不生成第二单。外部重启保存故障/报告高水位，不能重启清空订单使UNKNOWN消失。

## 5. 隔离与验收

所有请求只允许模拟模式、隔离账户和run；Web只能经平台受控场景访问控制端口。组件无真实券商凭证/网关出站，资源清理仅明确非活动测试范围。

最小数值Fixture：现金10000、买100股×10、测试费5，最终现金8995/持仓100；重复10次原Fill不重复入账。独立券商资产和组合账本可以通过故障样本产生差异，验证对账确实发现而非总返回相同。

验证T27～31、T42/43、T48～54模拟子项、VT03/04/06：进程重启持久性、接受响应丢失只查不重发、部分成交/撤单竞态、重复回报、跨run隔离、记录序列重放。业务状态全部NOT_RUN。
