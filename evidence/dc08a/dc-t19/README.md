# DC-T19 真实盘中主备切换验证

本目录保存实际交易日的 BaoStock→Sina 故障切换、600 秒半开探测和切回证据。每个交易日使用独立子目录 `YYYY-MM-DD/`，不得覆盖既有证据。

## 执行顺序

1. 盘前：运行 `pnpm dc08a:morning`，保存输出为 `YYYY-MM-DD/morning.json`；记录20只证券集合、活动订阅、服务健康和来源健康初始状态。
2. 盘中：由自动调度运行，不手工补采。保存每个窗口的 `observation-*.json`、覆盖报告、来源健康快照及错误/切换审计。
3. 盘后：运行 `pnpm dc08a:eod`，保存 `daily-report.json`、`health-report.json`、`observation-summary.json` 的当日副本。

## 必填观察项

| 观察项 | 通过条件 | 证据位置 |
|---|---|---|
| BaoStock 初始状态 | 盘中有真实请求，记录 `OPEN/CLOSED/TIMEOUT`、失败次数和最近错误 | `health-*.json`、来源审计 |
| Sina 接管 | BaoStock 失败后同一窗口由 Sina 完成，记录切换时间、证券、窗口和尝试次数 | `observation-*.json`、运行审计 |
| 600 秒半开探测 | 熔断打开后至少等待600秒；每个窗口最多一次探测；不得启动高频重连线程 | 健康快照时间戳、适配器审计 |
| 成功切回 | 半开探测成功后后续窗口来源恢复为 BaoStock，记录切回时间和来源 | 来源审计、原始响应 |
| 失败后继续降级 | 半开探测失败时继续使用 Sina，未重复发送同一窗口 | 运行状态、重复键/Outbox检查 |
| 延迟 | 记录 `scheduledFor`、请求开始/结束、来源响应和发布完成时间；计算调度延迟与来源延迟 | 运行 JSON、原始响应 |
| 原始字段 | 保存来源原始字段、时间戳、证券代码、OHLCV、amount、单位和错误码；规范化值单独保存 | `raw/` 与规范化 Artifact |
| 日终质量 | 20只×48窗口完成，960根唯一 Bar，0缺口，0待投递 Outbox，0重复 | `daily-report.json`、coverage 报告 |

## 判定规则

- 当日任何窗口失败、排队或出现缺口，即使盘后恢复，也只能标记 `recovered`，不能计入连续稳定日。
- 只在全天没有失败/排队/缺口且日终质量通过时，将该日计入 `completedDays`。
- HTTP 200、盘后补齐或历史 Fixture 不能替代盘中主源和切换证据。
