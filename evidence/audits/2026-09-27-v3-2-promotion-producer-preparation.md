# V3.2 PromotionRequest producer preparation

Date: 2026-09-27 (Asia/Shanghai)

## Scope

Added `services/research-automation-service/src/application/v32-promotion-producer.ts` as a pure application-layer constructor for the existing `v3.2-promotion-request-v1` contract. It requires a completed Runner Job tied to the exact TestRun and experiment; published Runner OUTPUT ArtifactRefs whose exact output roles are bound by the validation plan paths, Job ID, fencing sourceRef and deterministic artifact IDs; and a settled USD budget whose consumed amount does not exceed its reservation.

The constructor now consumes exact UTF-8 bytes for the versioned V3.2 data-manifest and validation-plan sidecars. It strictly validates their schemas, computes their SHA-256 values itself, binds both to the same TestRun/experiment, checks the validation plan's manifest hash against those exact bytes, and derives candidate source from the validated plan. The request contains no approval or Registry mutation field. New schemas, fixtures and compatibility rules are generated into the TS/Python projections.

The validation plan now declares candidate, generated-code and metrics output paths; the constructor verifies each role against the exact completed Runner Job, fencing sourceRef and deterministic path-derived artifactId. ## Limits

This is not yet the PromotionRequest producer workflow: it does not query persisted experiments, Runner Jobs, ArtifactRefs or the budget ledger; it does not automatically consume the parsed bundle result or submit to `quant-research-service`; and no V3.2 route, TestRun scenario or Web action calls it. Sidecars are parsed and their content hash is checked against Runner input bytes, but they are not persisted as Runner output artifacts or tied to repository-backed records. No candidate was submitted, no Qlib recomputation ran, and Registry state did not change. Candidate validation, Web/CLI acceptance, the V3.1 prerequisite and human acceptance remain `NOT_RUN`.

## Persistent evidence assembly follow-up

Added `V32PromotionRequestPreparer` to assemble the request through injected experiment, Runner Job, budget, ArtifactRef and content-store ports. It derives the content-addressed input ArtifactRef from the Runner Job, reads and hashes the exact bundle bytes, parses V3.2 sidecars and data files, resolves plan-declared output paths against the completed job's published fenced OUTPUT refs, and delegates final validation to the immutable request constructor. Request UUID/idempotency identity is deterministic from Runner Job identity so repeated preparation yields the same payload. Missing records return `WAITING`; complete evidence returns `READY_FOR_GATE_CHECK`, explicitly before V3.1 acceptance and without sending a request or mutating Registry. Seven focused tests cover deterministic retries, missing Job/input/sidecars, unsettled budget, content drift and output relabeling. This slice has no HTTP route and no live Quant submission.
