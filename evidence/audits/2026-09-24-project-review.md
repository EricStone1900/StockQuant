## 4. 优化与缺口，按优先级

### P1-A：先隔离数据库测试，保护真实观察

`scripts/test-market-data-integration.mjs:3` 默认连接本机 `market_data` 数据库，而它也是当前采集观察数据库。
`services/market-data-service/tests/integration/collection-run-postgres.spec.ts:168` 附近直接使 `lease_id=1` 的全局调度租约过期并由测试worker接管；`:190` 附近选择当前启用订阅，切到测试订阅后再切回。后续失败可能阻止切回。

这不是随机run后缀就能隔离的状态。普通V2 code suite会调用这个集成入口，可能影响正式观察。优先改为一次性测试数据库或隔离schema/专属租约；缺测试数据库明确退出2，拒绝回退到观察库；复验测试前后正式订阅、水位和租约不变。

### P1-B：验收工具存在可复现误判

1. `scripts/validate-json.mjs:32` 仅执行JSON.parse；`contracts:check`不校验JSON Schema、字段语义、无效样本或版本兼容。补Schema 2020-12验证、生成TS/Python类型和正反样本，是V1.1欠项。
2. `scripts/verify-stage.mjs:76`、`:107` 等check-only路径主要读取已保存assertions，而非重新读取领域账本/订单事实。V1.2路径还只查Qlib probe，没有核对传入run。
3. 本次在临时目录mock fetch做隔离复现：V2.4返回 `COMPLETED + assertions:[]` 时退出0；返回 `FAILED + FAIL断言` 时退出2。应拒绝空断言，并遵守FAIL=1、缺前置/观察未满=2。
4. `scripts/verify-version.mjs:28`～`:38` 只分析阶段表格，未校验版本总结、版本门禁勾选、必需场景数量和证据完整性。本次临时目录构造“表格PASS，但总结NOT_RUN且门禁未勾”，脚本仍输出PASS/退出0。当前真实仓库三版仍正确显示INCOMPLETE；这个复现揭示的是未来误放行路径。

以上临时复现未修改仓库计划或调用真实业务接口。应把阶段/版本必需能力、断言、证据及观察规则改成机器可校验清单，人工签署仍独立保存。

### P1-C：明确Paper观察覆盖，并补真实持续策略链

`services/platform-api-service/src/application/v24-live-observation.ts:46`～`:56` 明确HOLD-only，等待已独立批准的策略/Mandate接线。本次8个计入日的日终对账均为orders=0、fills=0。

没有订单本身不是失败，不应为了观察制造交易；但该证据只能证明采样、执行窗口进入、HOLD与空订单日终对账。不能外推为“真实日频信号→治理/风控→FakeBroker订单/成交→账本”的连续自动调仓已验证。阶段任务第2节仍未勾，需继续实现或按确切已有版本完成接线。

还需加强质量规则：当前handler使用证券中最新observedAt，可能掩盖其他证券陈旧；qualityForDate按事件数量而非唯一预期窗口集合验收，未严格验证执行窗口行情质量。建议逐证券新鲜度、预期窗口集合和迟到/重复事件单独断言；观察规则版本写入证据。当前8天按现有最低门槛复核成立，不能据此擅自改写历史计数。

### P1-D：澄清数据模块短期退出与20日长期观察门槛

### P1-E：补统一身份和研究回调真实性

当前平台 `sq_session` 是固定用户标识，session接口直接签发；部分早期阶段路由没有统一identity检查。研究HTTP入口接受Runner start/complete及预算结算写入，未见服务身份校验。限定loopback/内部网络降低暴露范围，但不等于设计要求的可信身份。

当前模型调用关闭，保持该边界。接真实模型/可信宿主执行器前，统一用户会话、服务身份、scope和run所有权；Runner完成及费用结算只接受可信执行组件，避免调用者自己填写完成事实。引用：`services/platform-api-service/src/bootstrap/app.module.ts:23`、`:90`；`services/research-automation-service/src/bootstrap/main.ts:71`。这是代码静态发现，本次没有伪造请求改变业务状态。
