# V3.3 owner-scoped Runner queue read slice

## Delivered

- Research Automation adds bounded `GET /v1/runner/jobs?testRunId=<uuid>&offset=<n>&limit=<n>`. The Postgres store filters the JSON job identity by exact TestRun and returns a deterministic page ordered by submission time and job ID; an expression index on TestRun/submission/job ID supports that access path. The in-memory implementation follows the same behavior.
- Research Automation authorizes the route for the Platform API Bearer only. Invalid/duplicate/unknown query parameters, malformed UUIDs, and limits outside 1–100 return 422.
- Platform adds `GET /api/v1/acceptance/v3/v3.3/runs/{testRunId}/research/queue`. It requires a user session, resolves the TestRun in that owner's scope and requires `stageId=V3.3` before forwarding with the Platform service Bearer.
- Added `v3.3-runner-queue-v1` JSON Schema, OpenAPI for both trust-boundary routes and a compatibility rule.
- Added a read-only Web view at `/acceptance/v3/v3.3`. It accepts an existing TestRun ID and shows queue rows, bounded pagination, empty state and raw response evidence. Initial delivery left the budget view `NOT_CONNECTED / NOT_RUN`; the follow-up below now reads page-scoped budget ledger facts. Dispatch remains `NOT_IMPLEMENTED`. The page cannot create runs or jobs.

## Follow-up: keyset pagination and Runner read-scope correction

- Added `GET /v1/runner/jobs/cursor` with a bounded opaque continuation cursor over `(submitted_at, job_id)`, matching the stable queue order and TestRun filter. Platform adds the owner/stage-scoped proxy and the V3.3 Web page uses cursors for queue navigation; existing offset queue/budget contracts remain available. Cursor contents are base64url-encoded, not signed; every request remains constrained to the supplied TestRun and the Platform-only route.
- PostgreSQL continuation integration now inserts a later-submitted job after reading the first page, then traverses remaining pages and verifies the preexisting jobs plus the new job appear once in stable order while a neighboring TestRun stays excluded.
- Real HTTP smoke exposed that Runner Host's single-job GET matcher also accepted a list URL with query parameters. Tightened that matcher to require one concrete path segment with no query string and added a regression assertion. The smoke now confirms anonymous `401`, Runner Bearer `403`, Platform Bearer `200`; 17 HTTP assertions pass with no database/model/order calls.
