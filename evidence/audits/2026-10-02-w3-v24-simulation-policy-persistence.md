# W3 V2.4 simulation policy persistence

The Trade Execution service now seeds the versioned `v24-snapshot-paper-policy` into its PostgreSQL database before opening readiness requests. The policy row is constrained to `PREPARATION_ONLY`, `PAPER`, `FAKE`, and `liveTradingEnabled=false`; policy identity and version columns must agree with the JSON document. An immutable-version repository rejects a changed digest for an existing version, and PostgreSQL rejects direct UPDATE, DELETE, and TRUNCATE attempts. Readiness loads that stored row and remains read-only. The policy is not shared with or used as a LIVE execution policy.

Validation passed: repository unit tests 2/2, Trade Execution typecheck/build, isolated PostgreSQL HTTP smoke (including direct database mutation rejection), Linux ARM64 container readiness, and the complete `pnpm verify:stage -- --stage V2.4 --suite code` (exit 0). The full suite also passed all four isolated Fixture Paper scenarios with Web TestRuns checked through CLI against the same IDs. Detailed structured assertions are in [the JSON audit](2026-10-02-w3-v24-simulation-policy-persistence.json); the full stage smoke is [here](2026-10-02-v24-paper-smoke-f478a606497845e3875dd8529bb19104.json).

The policy remains `PREPARATION_ONLY`; CN_A readiness is BLOCKED, US_EQUITY is REJECTED, risk evaluation and resource reservation are NOT_RUN, and order submission is disabled. Stale/unknown-source and expired-account pause/alert behavior, the continuous live-source chain, active deployment, real-source authorization, 20-day observation, and human acceptance remain incomplete. No active services, external market-data providers, or real broker were touched.
