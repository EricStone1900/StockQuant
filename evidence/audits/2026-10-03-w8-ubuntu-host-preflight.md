# W8 Ubuntu target-host inventory preflight (2026-10-03)

Added `scripts/w8-ubuntu-host-preflight.mjs` and a package entry `pnpm verify:w8:ubuntu-host`. The read-only probe records OS/distribution, architecture, logical CPUs, memory, available filesystem bytes for the project path, and selected Docker runtime identity. It refuses remote Docker endpoints, does not contact a registry, inspect credentials, or start/stop containers, and never treats inventory as release approval. Because minimum resource thresholds are not frozen, even a matching Ubuntu x86_64 host returns only `INVENTORY_ONLY`.

The probe was exercised first in the default sandbox, where access to the Docker Desktop Unix socket was denied, then through a controlled read-only retry against that local socket. The latter reported Docker Engine 28.0.4, `linux/aarch64`, Docker Desktop, cgroup v2, overlay2, 10 CPUs and 8,218,034,176 bytes of Docker daemon memory. The host remained macOS/aarch64 and the result remained exit 2 / `BLOCKED`; `linuxContainerRuntimeMatchesTarget=FAIL`. This is not target Ubuntu evidence. No Docker command was routed to a remote endpoint. Unit cases passed 4/4, including target Ubuntu remaining `INVENTORY_ONLY`, macOS/ARM/non-Ubuntu rejection, absent or mismatched Docker runtime rejection, and refusal of remote TCP Docker endpoints. `pnpm docs:check` and `git diff --check` passed after documenting the procedure.

The new command shortens host intake when an approved Ubuntu target is available, but does not complete target-host verification, resource-policy approval, deployment, data migration, formal backup, or Ubuntu observation. The exact runbook entry is in [the W8 maintenance review package](../../docs/operations/2026-09-30-w8-maintenance-package.md), and V3.4 remains `NOT_RUN`.
