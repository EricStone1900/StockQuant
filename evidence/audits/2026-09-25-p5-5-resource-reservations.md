# P5.5 persistent resource reservation preparation

Date: 2026-09-25. This implements and verifies an isolated portfolio account repository capability. It does not authorize a Paper strategy, expose an unverified internal route, place an order, or mark P5.5 complete.

`portfolio-risk-service` now has an additive `resource_reservations` PostgreSQL table and repository operations. BUY reservations lock the account row, bind owner/namespace/TestRun/account/currency, and ensure cash less HELD/UNKNOWN reservations remains nonnegative. SELL reservations bind the same scope and ensure position quantity less HELD/UNKNOWN reservations remains sufficient. The per-account order identity and idempotency key are unique; reusing either identity with a different payload conflicts. UNKNOWN remains held until an evidence-bearing authoritative outcome; terminal capture/release is idempotent only for the same outcome and evidence. The repository adapter is not exposed over HTTP because this service has not yet completed a trusted bearer identity boundary for these new callers.

Contracts added: `resource-reservation-command`, `resource-reservation`, and `resource-reservation-resolution`, with BUY/SELL and UNKNOWN fixtures and compatibility rules. `.env.example` documents the isolated `portfolio_risk_test` URL.

## 2026-09-25 implementation update

The earlier statement that reservations were not exposed over HTTP is superseded by this update. `AccountController` now exposes `POST /internal/v1/accounts/{accountId}/reservations` and `POST /internal/v1/accounts/{accountId}/reservations/{reservationId}/resolve`; only `trade-execution-service` with its own Bearer token can call these routes. Calls bind owner, namespace, TestRun and account scope. Resolution also requires evidence and a recognized outcome. OpenAPI now describes both operations and the shared Bearer scheme, and the contract checker enforces their presence and response sets.

`pnpm --filter @stockquant/portfolio-risk-service test:integration` now builds the service, defaults Vitest to the dedicated `portfolio_risk_test` database (unless an explicit isolated URL is supplied), runs the two reservation PostgreSQL cases, then starts a temporary service process for HTTP checks. Latest HTTP smoke passed: missing Bearer 401, wrong token 401, wrong caller scope 403, own snapshot 200, foreign owner 403, platform fill/reservation denied, reservation created 201, same-key retry replayed the same reservation, over-budget request 409, replay caller and foreign owner resolution 403, invalid outcome 400, UNKNOWN retained the hold, and authoritative cancellation released it. Workspace build/lint/typecheck/unit tests, FakeBroker and portfolio PostgreSQL integrations, contract/fixture validation, Python adapter, ops and market-data integration all completed successfully.
