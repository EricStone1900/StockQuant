# V1 Gate Classification: Ubuntu, Artifact Cleanup, and Active Strategy/Deployment

Date: 2026-10-09 (Asia/Shanghai)
Status: source-level reconciliation; no gate or product requirement changed.

## Findings

| Topic | Authoritative requirement and current boundary | V1 completion impact | Disposition |
|---|---|---|---|
| Ubuntu and target architecture | [Three-version delivery rules, §5](../../docs/prd/05-three-version-delivery.md) require V1/V2 to attempt the target-architecture smoke test and record gaps/emulation; the same section explicitly requires actual Ubuntu deployment/recovery/E2E for V3. [V1 plan, §2](../../docs/prd/v1-local-simulation/00-version-plan.md) identifies the x86 Ubuntu target and says to distinguish local, emulated and actual Ubuntu evidence. [V1 acceptance, §2](../../docs/prd/v1-local-simulation/99-acceptance.md) still has a generic target-architecture/performance/observation checkbox, and its current status separately records W8 target-host revalidation as NOT_RUN. | A Linux/amd64 emulation smoke can satisfy the common rule's V1 architecture-attempt requirement only when the report identifies emulation and its limited scope. It cannot satisfy the unresolved W8 host-specific revalidation if that item is confirmed as V1 scope. Current evidence does not prove a physical Ubuntu host run. | Keep W8 NOT_RUN. Do not silently lower the W8 item to an emulated smoke. The V1 PRD and common rules distinguish an architecture attempt from V3's actual Ubuntu deployment gate; the owner must clarify whether W8 host revalidation adds a V1-specific physical-host requirement before the V1 version gate is changed. |
| Artifact retention and physical cleanup | [V1.1 stage, §2](../../docs/prd/v1-local-simulation/01-environment-and-web-center.md) requires Artifact storage/reference/delivery lifecycle work and records that expiry policy, scheduling, cross-service reference protection and physical cleanup remain open. [OD-013](../../docs/decisions/open-decisions.md) explicitly forbids default expiry, scheduled transition and physical deletion until the owner decides. The [OD-013 decision package](./2026-10-09-v1-artifact-policy-decision-package.md) separates lifecycle state from byte removal and requires an all-producer reference check, dry-run and paired recovery before implementation approval. | Artifact integrity, owner/TestRun/hash binding, controlled reads, backup/restore and exact isolated resource cleanup remain legitimate V1 engineering requirements. A generated-Artifact retention duration and destructive byte reclamation are not currently specified as authorized behavior; inventing a default would alter product policy. | Preserve the V1 artifact-lifecycle gap and OD-013 as an owner decision. Do not enable expiry defaults, schedulers or physical cleanup. Isolated test-volume cleanup remains within its exact disposable-resource contract and is separate from deleting user/research Artifact bytes. |
| Active strategy | [OD-007](../../docs/decisions/open-decisions.md) records the owner's approval of a read-only NO_TRADE observation baseline only; holding period, rebalance, benchmark/portfolio, risk/cost and source-use parameters remain OPEN, and activity stays PREPARATION_ONLY. [Three-version delivery rules, §4](../../docs/prd/05-three-version-delivery.md) require FakeBroker/simulated accounts and reject LIVE writes/real brokers. | V1's fixed Fixture AUTO scenario verifies simulated authorization and execution behavior; it is not authority to activate an ongoing strategy or real account. Strategy activation is not a valid substitute for missing V1 acceptance evidence. | Keep active strategy activation disabled and OD-007 OPEN. Keep simulated Fixture/PAPER behavior testable under its fixed policy; do not connect real sources or brokers. |
| Active storage/API deployment | [V1.1 stage, §2](../../docs/prd/v1-local-simulation/01-environment-and-web-center.md) still lists deployment of unified TestRun storage to the active API and rollback validation. The V1 completion plan and repository instructions require exact active-resource inventory, paired recovery copy, migration/double-write/rollback rehearsal, then a separate approval for the actual operation; current instructions explicitly do not authorize an active cutover. | Isolated PostgreSQL migration/dual-store/persistence tests prove code behavior in disposable databases, not that the active API was cut over, backed up or rolled back. V1.1 remains incomplete for this item. | Preserve NOT_AUTHORIZED/NOT_DEPLOYED. Complete preparation and evidence on isolated copies; do not run an active cutover until the owner approves the concrete resource list, window and rollback package. |

## Owner decisions and remaining evidence

1. Clarify whether V1 W8 means a physical Ubuntu-host run or only a target-architecture smoke with emulation explicitly recorded. The common delivery rule alone does not make actual Ubuntu deployment a V1 gate; it does require that for V3.
2. Resolve OD-013 before deciding Artifact expiry defaults, scheduling or physical deletion.
3. Resolve OD-007 before any ongoing strategy activation; current V1 simulation evidence can continue with fixed Fixture policies and FakeBroker.
4. Approve any active V1.1 storage/API cutover only after reviewing exact resources, paired backup evidence, migration and rollback rehearsal. No approval or operation is implied by this classification.

This classification does not close any of those gates. It records the source-level distinctions so future implementation and acceptance work do not infer policy from code or emulated test results.
