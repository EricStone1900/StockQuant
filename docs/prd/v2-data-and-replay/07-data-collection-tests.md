# 共享数据采集：测试案例与中断恢复手册

版本1.1，2026-09-12。关联[开发计划](./06-shared-data-collection-plan.md)和[进度表](./08-data-collection-progress.md)。DC-03确定性单元测试已PASS；真实交易日、后台进程和人工验收仍NOT_RUN。操作手册为DRAFT_NOT_EXECUTABLE，DC-02/07实现入口并亲自执行后才可更改。

## 1. 测试输入和证据约定

DC-01新增不可变Fixture（目标位置 fixtures/v2/data-collection/v1），Manifest按现有Fixture规范生成。固定seed=20260912；以注入Clock构造一个具有沪深早/午两个时段的完整测试日、休市日、未知日历日期、US DST及提前收市案例。合成市场日历明确标Fixture，不冒充官方日历。股票用600000.SH、000001.SZ，再扩到冻结20只集合。

正常样本每只每完整日48根，使用可手算量价与成交额；另提供缺1根、重复1根、未闭合Bar、NaN/Infinity、负数、单位差100倍、复权不一致、来源迟到/修订、全日停牌、部分时段停牌、日历覆盖不足样本。原始响应录制需来源/采集时间/许可和脱敏；适配器模拟测试与真实接口测试单列。60日样本为Fixture，只验证算法。

每例保存：用例版本、输入Hash、代码/工作区Hash、依赖锁/镜像/迁移、环境架构和资源、命令/原始退出码、runId/testRunId、故障注入顺序、expected/actual、日志/截图、规范数据Hash。原失败追加保留。预期故障正确处理可使测试PASS，但业务任务仍保留失败/等待状态。

## 2. 用例矩阵

所有用例当前为NOT_RUN。表中“恢复”必须操作实际隔离任务/组件，不能只修改状态字段使断言通过。

|---|---|---|

| DC-T02 DB/共享 | 两项目同源同窗口同时提交，各重试一次；取消其中一个订阅 | 一次物理采集、两个授权引用；剩余项目完成；取消不删除共享产物；相同幂等键不同载荷拒绝 |

## 3. 测试实现与执行顺序

新增DC-T25（真实短期运行，NOT_RUN）：DC-07部署后3只跨沪深证券连续2实际交易日自动运行，再20只至少1实际交易日；检查盘中、日终补采、调度ID、心跳和逐日覆盖。预期：无需人工逐次触发，闭合窗口及时性符合冻结来源能力，每日无未解释缺口，故障恢复证据可查，正式20只订阅保持启用且不依赖浏览器。故障演练在隔离任务执行，不破坏正式数据；该测试不能替代60日覆盖。

目标测试组织：服务内 tests/unit/collection-*.spec.ts、tests/integration/collection-*.spec.ts；Python适配器在自己的锁定环境内使用pytest；浏览器用现有Playwright组织新增采集用例。这些目标文件当前未创建。禁止把当前根test:integration的V1.1结果作为DC-T12～14通过。

1. DC-01冻结Fixture和预期；测试先失败以验证拒绝/缺失路径，随后实现相应工作包。
2. 每包执行受影响的lint/type/unit/contract；持久化包必须执行真实PostgreSQL，调度包执行实际后台进程。
3. 注册V2.5采集normal/rejection/recovery子场景；code套件列出真实测试文件和退出码，browser套件不能为空。
4. DC-04执行真实源能力；网络故障证据与人为注入分开，不无界重试直到碰巧通过。
5. DC-06执行Web/CLI同run复核；DC-07执行真实容器、故障与备份恢复。
6. DC-08A执行DC-T25并完成开发交付签署，通过后恢复主项目。DC-08B每日记录覆盖，DC-T23真实覆盖不足返回2；此等待不否定已完成的开发交付，但不能将长期数据验收标PASS。

## 4. 运行中断恢复操作手册（待实现命令）

启动前：确认部署环境、DB/Artifact卷、日历版本、订阅修订、20只清单Hash、来源能力、磁盘、唯一活动调度器；记录runId。不要使用/tmp作为正式数据存储。

中断后按以下顺序操作，参数ID必须从实际记录取得：

1. 使用目标命令 `pnpm data:status -- --run RUN_ID` 查询任务、最后持久检查点、租约、文件/DB状态及错误；保存日志，不重新创建相同工作。
2. 按错误类型恢复网络、DB、磁盘挂载或受影响服务；先核对隔离目标，禁止删除共享卷。重启命令在DC-07按实际Compose服务/部署位置填写并演练。
3. 确认原Worker已失租约；使用 `pnpm data:resume -- --run RUN_ID --expected-version N` 恢复，检查无重复发布、旧Worker无写入权。
4. 使用 `pnpm data:coverage -- --subscription ID --from DATE --to DATE --check-only` 查缺口；必要时用计划定义的backfill命令补采；超范围缺口标UNRECOVERABLE。
5. 重跑同run只读断言，附新的检查记录；失败历史保留。解除告警必须有实际恢复证据。

数据库/磁盘灾难：暂停采集→验证备份Hash→恢复到新隔离卷/库→核对版本引用与检查点→计算RPO缺口→补采→人工核对后切换唯一调度实例。没有可用备份且超来源回溯期限时不能保证数据可恢复，明确列出损失范围。

DC-07交付前必须替换目标命令为实测入口，并填写：实际工作目录、Web地址和按钮、服务名称、非秘密配置、身份建立方法、Fixture/源数据Hash、命令退出码、超时、备份路径、恢复步骤及报告。未补齐时手册保持DRAFT_NOT_EXECUTABLE。
