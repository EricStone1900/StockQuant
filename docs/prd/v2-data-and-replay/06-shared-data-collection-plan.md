计划版本：1.1；日期：2026-09-12；状态：PLANNED。本文落实用户提出的多项目复用、指定市场交易时段采集、每日任务、本地累积60个实际交易日、测试及故障备用要求。本次交付为开发计划，未启动采集或新增定时任务。

执行入口：[进度与接续记录](./08-data-collection-progress.md)；测试入口：[测试与恢复手册](./07-data-collection-tests.md)。遵循[三版规则](../05-three-version-delivery.md)、[市场契约](../03-market-rules-and-contracts.md)和[V2.5](./05-data-scale-and-v2-acceptance.md)。工作包编号 DC-00～DC-08 是 V2 数据能力扩展的内部编号，不是已注册的 verify:stage 阶段，不改变原 V2/V3 门禁。

## 1. 目标、边界和已知基础

在当前仓库中建设可独立运行的采集 Worker，由 market-data-service 拥有数据、质量与发布事实；多个项目通过认证 API 提交需求、查询和导出。StockQuant 是首个使用方。先实现 A 股固定20只股票的5分钟数据；支持日线等类型的契约扩展，但新增类型和市场需独立实现、测试和来源核验。美股日历逻辑用 Fixture 验证，真实源保持未启用。其他项目复用数据必须具备相应许可及访问权限。

现有在线快照监控≤100只、30/20分钟采样约束继续有效。新的历史分钟归档订阅与在线监控分别配置和统计，不能通过多项目配置绕过 StockQuant 在线池上限。历史库也不能由今日监控池替代历史证券范围。采集不触发策略激活或交易，保持 FakeBroker 边界。

| 基础项 | 核对结果 | 本计划复用方式及缺口 |
|---|---|---|
| 市场数据服务 | 当前实际为 TypeScript，src/main.ts 使用内存 Map 保存部分导入/任务状态；架构文档 Python 是目标设计 | 保留服务入口，按领域/应用/端口/适配器拆分新增部分；先落持久状态，不假定已有持久采集队列 |
| BaoStock 5分钟导入 | 历史证据为20只、55,680行、58实际交易日 | 复用解析/受控超时经验；生产化前补锁定依赖、持久任务和故障测试 |
| BaoStock 稳定性 | 历史探针出现 TIMEOUT，未通过稳定性门槛 | 默认主源偏好可以配置，但盘中能力必须先测 |
| 新浪分钟源 | 历史证据约40交易日的近期数据 | 字段、量额单位、盘中延迟和许可待核；报价接口不等于分钟接口 |
| TDX 文件脚本 | 已有入口；记录为静态、模拟成功、缺文件测试通过 | 真实文件未提供；不能标记完整备用能力，需补生产级防覆盖及真实解析验证 |
| V2.4观察 | 已有独立观察安排；本次未读取调度器或重新核验进度 | 不重复创建、不改其计数；20日 Paper 与60日数据覆盖分别验收 |

上述既有数字来自仓库 docs/evidence-v2.5.md，属于历史记录，本次未重跑数据源。新模块全部业务测试初始 NOT_RUN。

## 2. 需求与完成定义

### 2.1 本次任务边界及恢复主项目的条件

按用户最新安排，先集中完成本模块，再继续主项目其他开发。顺序为DC-00～DC-07→DC-08A；等待真实交易时段时，可推进本模块内部不依赖观测结果的工作。主项目暂停新增功能，允许本模块必需的兼容修改和原有功能回归；既有V2.4观察保持运行，不重置或重复创建。

DC-08保留原编号，细分DC-08A“启用与短期验收”和DC-08B“60日数据验收”。本次开发结束须同时满足：

- DC-00～DC-07实现及所需测试通过；盘中采集和主备真实能力有证据，不能用盘后或模拟结果代替。
- DC-08A通过：部署后3只跨沪深证券连续2个实际交易日自动运行，覆盖盘中及日终，无未解释缺口；故障/恢复演练通过；扩大至冻结20只后至少完成1个实际交易日的自动采集、质量复核与日终补采。
- 正式调度唯一启用；重启恢复、持久数据、告警、备份恢复、管理页面和多项目接口通过验证；操作手册VERIFIED_EXECUTABLE，用户完成本模块人工验收。
- 交接记录列明部署位置、订阅/调度ID、清单Hash、数据/备份位置、下次执行时间、覆盖进度、未解问题、主项目下一待办及前置条件。

满足以上条件后标记“本次模块开发交付完成”，再恢复不依赖60日数据的主项目开发。DC-08B后台持续积累，未满或有缺口保持WAITING，不阻塞本次开发交付，也不代表“60日数据验收完成”或“V2全部通过”。DC-08A实际交易日不能加速替代，休市或缺必需外部能力时保留等待/阻塞，不擅自缩短门槛。

## 3. 架构与持久化契约

| 组件 | 所有权和目标位置 |
|---|---|
| 领域/应用/API | services/market-data-service/src/ 下新增分层模块；拥有订阅、任务、数据版本、缺口及授权 |
| 采集 Worker | market-data-service 的独立进程/容器；只通过受控 Python Adapter 调 BaoStock/Sina；Python 独立 pyproject 与 uv.lock，安装在构建期，禁止每次定时运行临时下载依赖 |
| 调度 | 接入既有编排边界；DC-01先核实现有调度持久性。若不足，由编排层持久轮询到期订阅，经市场数据API创建任务。唯一启用一个调度后端，不同时叠加应用/宿主/助手调度器 |
| 正式Web与验收 | apps/web 和 platform-api-service；页面展示/发命令，领域事实由数据服务提供 |
| 元数据/Artifact | 市场数据域专属PostgreSQL库和持久卷；原始响应和规范数据按市场/频率/日期/证券分区，版本化不可变；其他项目不直连数据库 |

逻辑实体在 DC-01 生成 Schema 和迁移：ProjectConsumer、CollectionSubscription、SubscriptionRevision、ProviderCapability、CalendarVersion、CollectionRun、PartitionAttempt、Checkpoint、GapRecord、DataVersion、ArtifactRef、AlertEvent。每条订阅固定 projectId、市场、securityUniverseVersion、类型/周期、目标日期、来源策略、日历/质量规则版本、时区、更新/保留策略、quota 和 expectedVersion。变更创建修订，正在执行的任务使用原快照。

分钟记录包含 securityId、market、barStart/barEnd、availableAt、ingestedAt、sourceId、sourceRevision、RAW复权类型、OHLC、volume及单位、amount及币种、原始Artifact引用、质量状态。价格和量额用明确精度的十进制表示；缺成交额时记录 null/UNAVAILABLE，禁止以零或 close×volume伪造。若消费契约要求成交额，则这份来源不能满足完整要求。

实时采集以真实观察时间保守界定可用性；历史导入只有 barEnd 时不得声称知道历史实际发布时间。迟到、修订及从新浪切回BaoStock均生成新版本，回测固定DataVersion/asOf，不回写过去可见事实。未经校验的盘中Bar保留 provisional，不能作为完整Bar发布。

调度幂等键：subscriptionId+subscriptionRevision+windowStart+windowEnd+jobKind；物理采集去重键包含source、市场、证券、周期、RAW/复权、窗口及适配器版本。仅对权限/许可兼容的项目共享物理结果；各项目任务和授权仍独立。取消一个项目的订阅不取消其他项目仍需要的共享任务。

任务状态：QUEUED→RUNNING→COMPLETED；可转 WAITING_RETRY、WAITING_DEPENDENCY、PARTIAL、FAILED、PAUSED、CANCELLED。分区状态与任务状态分开。持久租约+心跳+递增fencing token保护写入，旧Worker租约失效后不能发布。调度水位和数据完整性水位分开：处理过某天不等于该天数据完整。

发布顺序：原始文件写入并校验→规范临时文件校验→不可变Artifact落盘→DB事务提交版本/检查点/Outbox。消费事件幂等；重启识别孤立文件和已提交版本，不发布半文件。DB故障不得确认任务成功；磁盘故障不得推进游标。

## 4. 调度、默认参数与数据积累

下列是待测试的初始配置，不是供应商承诺。实际股票清单优先复用现有20只样本清单并冻结Hash；日期从任务实际启用日开始，若需过去数据则单独backfill。

| 参数 | 初始方案 | 核验/变更规则 |
|---|---|---|
| 首批范围 | StockQuant、CN A股、20只、MINUTE_BAR/5m、RAW | 交易所日历映射明确；新增证券单独计覆盖 |
| 市场时区 | Asia/Shanghai；UTC持久化、本地时间展示 | 从版本化CalendarSession取交易窗口；未知日期停止实时调度并告警 |
| 调度检查 | 每60秒检查到期窗口 | 每个闭合5分钟窗口+候选发布延迟120秒；DC-00实测后调整，不能保证2分钟发布 |
| 收盘补采 | 候选当地18:30，次交易日开盘前复核 | DC-00验证上游发布情况后冻结；交易时段采集和盘后补采独立jobKind |
| 滚动补采 | 最近5个交易日并扫描全部未解GapRecord | 老缺口优先于来源保留期限到期；历史大批量队列低于当日采集优先级 |
| 超时/重试 | 单次30秒，每源每窗口最多3次；退避5/15秒加记录的抖动 | 受总窗口预算约束，过期转补采；同源总并发1，初始请求间隔≥1秒，DC-00按实测限额收紧 |
| 熔断 | 连续3次可重试失败打开5分钟，然后单探针半开 | 字段错误/许可拒绝直接禁用该能力，不能靠高频重试解决 |
| 资源候选 | 1个Worker、1 CPU、1GiB内存；剩余磁盘<max(5GiB,卷容量10%)暂停新写 | DC-07测量后冻结；记录配额、公平性与积压，不自动扩池 |
| 保留/备份 | 60日验收冻结数据保留；默认不自动删除原始证据 | 每日版本一致备份到独立介质；正式路径未配置则备份验收BLOCKED |

提前收市、DST、跨年、补充休市来自版本化交易日历；不能仅用周一至周五 cron。午休/闭市不创建新的盘中窗口，但允许补采已闭合窗口。重启按持久水位重建缺失任务，合并窗口而非补发大量逐分钟触发。关闭Web不影响采集；机器关机期间无法采集，只能恢复后在来源回溯范围内补采。

60日验收固定证券集合和连续60个市场交易日窗口；逐证券逐日检查应有Bar时间集合。正常完整A股交易日通常48根，特殊规则由冻结日历和来源语义确定。停牌/上市/退市需权威状态证据，标明有效豁免，不生成假Bar；状态不明算缺口。若测试要求每只都有60个实际有成交日，则须延长采集窗口，不能把停牌豁免当成交数据。日期跨度或总行数均不能单独证明完整。

纠正此前命令示例的范围误解：2024-01-02至2024-03-29的已有样本记录为58实际交易日，不能作为严格60日验收窗口。60日累计数据验收与“第二来源独立覆盖60日”分别报告；主备混合数据集通过不等于新浪独立覆盖60日。来源回补可提前完成历史覆盖，但不能冒充运行了60个实际交易日。

## 6. 服务错误与备用策略

| 故障 | 自动处理 | 备用与恢复条件 |
|---|---|---|
| BaoStock超时/未登录/限频 | 有限重试、独立会话、强制回收超时子进程、熔断 | 同窗口尝试能力匹配的新浪；恢复半开探针通过后主源复测，切换写审计 |
| 新浪缺amount/单位未知/旧数据 | 保留原始响应，隔离不合格行 | 不允许不完整备用冒充全字段数据；等待主源/人工合法文件，缺口保持OPEN |
| 两源均不可用/网络断开 | 持久重试时间和GapRecord；合并告警 | 恢复后先补临近过期缺口；回溯范围外转UNRECOVERABLE，提供文件导入或经授权的新来源，不承诺必可恢复 |
| 调度器中断/机器休眠 | 持久到期窗口及心跳缺失告警 | 重启重建未处理窗口；长期在线Ubuntu可替代Mac执行，单活租约防双机重复 |
| Worker崩溃/卡死 | 租约过期后接管，使用原任务ID/幂等键 | 检查点续跑，拒绝旧fencing token；半文件不发布 |
| DB/消息系统不可用 | 不确认完成、不推进水位；Outbox持久待发 | DB恢复后重新领取；消息故障可由持久任务轮询继续，不能改用内存当已持久化 |
| 磁盘满/文件损坏 | 停止新发布并告警；核验Hash | 从校验合格备份恢复到隔离目录，再核对元数据；不删除既有证据腾空间 |
| 日历失效/时区配置错误 | 阻塞受影响市场，其他市场可继续 | 更新可信日历版本、审计受影响窗口并补采；禁止工作日推算代替 |
| 上游修订/主备不一致 | 建新候选版本、记录差异 | 按冻结容差/规则选择；严重差异进入隔离，旧版本可查询但标时效 |
| 告警通道不可用 | 事件写本地持久Outbox，Web标未送达并重试 | 站内状态始终保留；外部目的地未配置不得称已发送 |
| 发布版本失败 | 暂停调度、保留队列/原始证据 | 回滚到兼容上个镜像；迁移采用expand/contract，破坏性迁移不自动回滚数据库 |

候选运维目标：进程恢复后10分钟内恢复调度；依赖恢复后30分钟内完成首批20只当日补采（受源限额制约，DC-07测量）；已确认持久发布在进程重启场景RPO=0。主机/磁盘灾难恢复目标RPO≤24小时、RTO≤4小时需独立备份与实际演练，未验证保持NOT_RUN。超过目标记录失败和原因，不能修改目标来掩盖失败。
