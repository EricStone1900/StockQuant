# V3.1 运行配置与 Runner 准备契约

状态：准备中；不代表真实 RD-Agent、模型 Provider 或 Runner 已验证。

## 已确认的目标架构

- **Mac M1**：开发、契约/服务/Web 验证和小样本 CPU 研究，优先 `linux/arm64` 容器；需要时用 `linux/amd64` 模拟做功能烟测，不作性能结论。
- **Ubuntu**：正式目标暂定 `x86_64`，使用 `linux/amd64` CPU-only Controller、RD-Agent Runner 和 Qlib Runner；不把 GPU 作为前置条件。
- **资源基线**：先按单并发、小样本执行；主机和 Runner 的 CPU、内存、磁盘、超时及输出上限需在真实 Ubuntu 烟测后冻结。
- **迁移规则**：从同一源码、锁文件和镜像构建目标架构，不复制 Mac 虚拟环境或本地编译产物；数据库和 Artifact 单独备份/恢复并校验 Hash。

决策记录见 [`ADR-0007`](../../../docs/decisions/ADR-0007-v3-cpu-target-architecture.md)。

## 配置来源

当前 Compose 继续使用 `STOCKQUANT_RUNNER_MODE=NOT_CONFIGURED` 和 `STOCKQUANT_MODEL_GATEWAY_MODE=NOT_CONFIGURED`。研究服务启动时校验 `RESEARCH + FAKE + LIVE_TRADING_ENABLED=false`；不满足时拒绝启动配置，避免把研究服务切到真实交易边界。

已确认的模型配置（仅非秘密元数据，当前仍不启用调用）：

| 用途 | Provider | 模型 | Base URL | 凭证引用名 |
|---|---|---|---|---|
| Chat | DeepSeek | `deepseek/deepseek-flash` | `https://api.deepseek.com` | `DEEPSEEK_API_KEY` |
| Embedding | SiliconFlow | `litellm_proxy/Qwen/Qwen3-Embedding-4B` | `https://api.siliconflow.cn/v1` | `SILICONFLOW_API_KEY` |

RD-Agent 来源已冻结为官方仓库 `microsoft/RD-Agent` 的 `v0.8.0`，完整 commit 为 `274e274d5dbb72cc2ea139d1a7c93d73ce9b1198`。来源证据见 [`rd-agent-source-v0.8.0.json`](../../../evidence/local/V3.1/rd-agent-source-v0.8.0.json)。该版本的 Python 下限为 3.10；项目已生成 CPU-only `linux/amd64` Runner smoke 镜像，证据见 [`runner-image-2026-09-22.json`](../../../evidence/local/V3.1/runner-image-2026-09-22.json)，原生 Ubuntu 兼容性仍待验证。

## Runner 任务协议

Runner 任务必须引用 `testRunId`、`experimentId`、不可变镜像 digest、输入 Artifact 和隔离输出 namespace。资源限制、网络策略和失败状态随任务提交，不能由生成代码自行扩大。

协议 Schema：[`v3.1-runner-job.schema.json`](../../../packages/contracts/research/v3.1-runner-job.schema.json)。当前已生成并验证 Runner digest，但 Compose 仍保持 `STOCKQUANT_RUNNER_MODE=NOT_CONFIGURED`；只有可信宿主适配器能使用该 digest 生成启动计划，API 容器不得挂载 Docker Socket。

本地启动计划实现将资源上限固定为 2000 millicpu、4096 MiB、3600 秒和 128 PIDs；输入/输出目录按 `managedRoot/{inputs|outputs}/{testRunId}/{experimentId}/fence-{token}` 隔离，并解析到该作业的精确路径。单任务宿主编排函数已经接通领取、输入bundle物化、可注入executor、周期心跳、输出采集/Artifact发布和完成回写；测试证明心跳失效会取消executor且不提交输出/结果。但它尚未接入常驻Host进程，executor目前仍是注入边界，且没有证明杀掉Docker CLI会同时终止daemon里的容器，因此不能标记真实Runner限额/失租终止验收通过。输出协议限制单Artifact 8 MiB、总量32 MiB、64个文件、深度16；这些软件拒绝边界不是Mac/Ubuntu容量声明。

V3.1 增加 PostgreSQL 预算账本表与阶段行锁：相同实验/金额重复预留幂等；UNKNOWN 继续占满预留并拒绝重试；核实原实验后可结算实际费用；已结算费用不可改写。API 启动时初始化账本结构和 V3.1 限额。真实模型任务当前仍未接入该预留/结算调用链，运行时模型门禁继续 `NOT_CONFIGURED`，故费用保护尚未完成端到端实证。

硬性拒绝项：Docker Socket、模型/控制器凭证、业务数据库、其他 run namespace、未授权文件、未授权网络、真实券商和生产 Registry。

## Artifact 引用

所有输入、生成代码、日志、指标、错误和候选均使用带 SHA-256 的 ArtifactRef，路径必须包含 `research/{testRunId}/{experimentId}`。失败 Artifact 保留，不因重试覆盖；新重试使用相同实验关联和新的步骤/Artifact ID。

协议 Schema：[`v3.1-artifact-ref.schema.json`](../../../packages/contracts/research/v3.1-artifact-ref.schema.json)。

## 服务身份实现进度（2026-09-25）

项目所有者确认研究服务采用每调用方独立Bearer Token。平台API→研究服务准备路由、平台取消Job路由及Runner Host claim/heartbeat/complete路由按最小scope鉴权；研究服务使用PostgreSQL原子claim、30秒租约和单调fencing token，过期接管或主动取消后拒绝旧worker续租/完成。缺/错令牌、越权、并发领取、取消和fencing均有自动验证。Host API支持租约绑定INPUT读取与OUTPUT发布，严格JSON契约/safe materializer和fence目录已接入单任务编排；隔离HTTP+PG smoke启动实际独立Host进程，固定冻结Docker镜像完成claim、heartbeat（数据库租约到期时刻向后推进）、执行、Artifact持久化和complete；另一次SIGKILL恢复验证中，Host 2在30秒租约过期后以token 2接管并清除Host 1的daemon容器，输出Hash匹配，旧租约发布返回422。60秒运行代码的取消HTTP smoke核实Job终态`CANCELLED`、heartbeat fence、活动容器移除、无OUTPUT和费用只结算一次。监督器超时/OOM/输出边界及daemon强制清理由独立smoke验证。Host进程支持SIGINT/SIGTERM清理，须显式TestRun scope，默认NOT_CONFIGURED且关闭态不发claim。新路由未部署到活动研究容器；没有生产长时间运行、原生Ubuntu或真实模型运行证据。V3.1 normal/rejection/recovery、同TestRun只读CLI核对、code suite和Web E2E证据见[2026-09-25 P7.2记录](../../../evidence/audits/2026-09-25-p7-2-service-identity.md)，容器烟测见[P7.3记录](../../../evidence/audits/2026-09-25-p7-3-offline-runner-smoke.md)及[P7.5记录](../../../evidence/audits/2026-09-25-p7-5-fixed-pipeline-smoke.md)。这些是准备范围工程证据，不代表真实研究实验、预算端到端或阶段人工验收通过。

Artifact并发/恢复补充（2026-09-26）：OUTPUT发布事务现在锁定Job行，重新核验当前fence，在同一PostgreSQL事务中保存ArtifactRef与Job的ArtifactRefs；平台取消更新同一行，因此取消先发生时不会写出，发布先发生时取消等待并保留该产物引用。取消后旧Runner Host迟到发布的HTTP smoke返回409，确认无文件、无ArtifactRef；fence token 1已发布的引用在token 2接管完成后仍保留。取消/发布竞态及跨fence留存的专用PG 14/14通过，研究服务单测95/95。新的固定镜像正常HTTP→Artifact smoke通过。文件系统写入与数据库提交无法组成单一事务，新增`artifact:reconcile`默认只读巡检可发现缺失PUBLISHED文件、引用Hash不符、过期孤儿和近期未登记文件；专用PG crash-window用例实际在文件写入后SIGKILL子进程，再由PG引用清单核实该孤儿的身份/字节数/SHA（TestRun `crash-b92cfa3d81474fde8aea765b1a9bae48`）。显式隔离需暂停发布者与Runner Host，移至同文件系统外部目录并保留Hash manifest，不会自动删除。巡检没有运行于活动Artifact卷；Docker daemon/宿主掉电故障、隔离维护演练、周期备份与活动PG/Artifact联合恢复仍未验证。详细证据见[P7.5取消与Artifact审计](../../../evidence/audits/2026-09-25-p7-5-fixed-pipeline-smoke.md)和[P7.2身份及孤儿巡检](../../../evidence/audits/2026-09-25-p7-2-service-identity.md)。
