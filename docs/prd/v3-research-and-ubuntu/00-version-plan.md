# V3 RD-Agent 自动研究与 Ubuntu 交付：开发计划

## 1. 目标和范围

真实RD-Agent小规模实验、独立复算和人工晋升接入已验证模拟平台，扩展研究容量并完成Ubuntu部署及Web回归。

本版纳入RES-01～04及必要模型网关/沙箱能力，属于原D7/R3子集和部署强化。六角色Agent、Memory自动学习、复杂Ensemble/市场状态策略及真实券商不在本轮必交范围，不宣称原R2/R3全部完成。

## 2. 数据与环境

复用已签署的小数据版本；真实模型调用先1～3轮、计算并发1。冻结训练/验证/测试区间及预热，研究晋升优先用未用于搜索的验证窗口/独立保留集，反复看过的测试集不能继续称未见测试集。

Mac M1优先Linux ARM64容器，先验证依赖再承诺原生支持。Linux AMD64作为目标Ubuntu为x86时的验证平台，Ubuntu ARM64则按实际目标调整。按[共同规则](../05-three-version-delivery.md)分别记录本地、模拟架构及真实Ubuntu证据。Web开发服务器可原生热更新，阶段验收必须覆盖容器服务。

## 3. 阶段顺序

| 阶段 | 交付 | 依赖 | 状态 |
|---|---|---|---|
| [V3.1](./01-rdagent-small-experiments.md) | 真实 RD-Agent 小样本实验闭环 | 本文件前置条件；详细依赖见阶段文件 | NOT_RUN |
| [V3.2](./02-candidate-validation-and-promotion.md) | 独立复算、人工批准与模拟策略晋升 | V3.1；详细依赖见阶段文件 | NOT_RUN |
| [V3.3](./03-research-scale-and-recovery.md) | 研究扩容、预算与持续运行 | V3.2；详细依赖见阶段文件 | NOT_RUN |
| [V3.4](./04-ubuntu-migration-and-release.md) | Ubuntu 迁移、全阶段 Web 回归与最终交付 | V3.3；详细依赖见阶段文件 | NOT_RUN |

以功能纵向切片交付；服务内部仍采用S0～S6生命周期。每阶段先冻结场景和预期，再同时开发后端与Web，执行自动检查后人工验收。后续独立工作可推进，但未通过的依赖不能被假成功替代。

## 4. 每阶段必交材料

- 任务清单及接口/数据/状态变更，更新的依赖锁、镜像与迁移。
- 正式功能页与验收中心场景：正常、拒绝/异常、重试/恢复中适用项。
- 固定数据和假依赖清单；实际组件与Fixture分开标记。
- 自动检查报告、浏览器截图、业务ID/Trace与人工签署。
- 运行/排错说明、已知限制、后续阶段所需契约和性能缺口。

## 5. 验收口径

本版各阶段[测试](./90-test-plan.md)和[验收](./99-acceptance.md)均需完成。流程成功、自动断言通过与人工批准分开保存。未跑、缺少数据/凭证/主机、观察期未满均保留NOT_RUN；业务不变量失败为FAIL。小数据通过只证明对应范围，不能推算全量性能或收益有效性。

## 6. 开发工作包约定

每次开始一个阶段，读取该阶段文件及共同规则，把复选任务作为本次边界。先确认已有工作区改动和依赖状态，按契约→最小后端→同步Web→异常→证据推进。不得仅搭空页面就报阶段完成；不得接入真实券商，也不得把假订单变成实际券商测试单。
