# V3.4 Ubuntu 迁移、全阶段 Web 回归与最终交付

状态：NOT_RUN。版本入口：[README](./README.md)。共同约束：[三版共同规则](../05-three-version-delivery.md)。

## 1. 前置与范围

三版必需阶段通过；目标Ubuntu主机架构/资源已记录，V2连续观察证据满足要求；真实券商仍不接入。

本阶段所有订单、券商资产和成交均来自隔离模拟环境。真实业务数据库、Qlib或RD-Agent在声明“已验证”时必须真正执行；替身需独立标注。

## 2. 开发任务

- [ ] 冻结Ubuntu发行版/CPU架构、镜像/锁文件、迁移与契约版本；从同一源码构建目标架构镜像，不复制Mac虚拟环境或本地编译扩展。
- [ ] 部署core/data/research配置，迁移数据库、行情Artifact和模型；named volume需显式备份恢复，密钥通过环境引用重新配置，验证权限/挂载和内容Hash。
- [ ] 独立部署研究执行环境，核心平台无宿主Socket；在Ubuntu重跑实际RD-Agent小实验及沙箱验证。
- [ ] 重跑V1～V3固定场景、分钟回放、持久化/检查点/备份恢复；资金精确一致，研究浮点按已冻结容差比较，记录差异。
- [ ] 执行Ubuntu真实时钟Paper连续运行、服务重启/断网和错过窗口恢复；建议至少5个实际A股交易日并覆盖一次日终，不将Mac观察冒充Ubuntu实测。
- [ ] 交付Web操作指南、验收中心目录、部署/升级/回滚/恢复/清理说明、版本证据包、未覆盖范围及真实券商后续清单。

## 3. 同步 Web 开发

正式页：Ubuntu运行环境/模式、健康、任务与全部业务页。验收页：Mac/Ubuntu证据对比、三版阶段签署、历史运行只读及测试操作后端权限。

验收中心路径：`/acceptance/v3/v3.4`（目标路由）。场景参数提交到后端TestRun编排接口，后端调用业务API并汇集证据。浏览器不直接写领域数据，不自行判定成交。该阶段至少提供正常、拒绝/异常场景；适用时增加重试/恢复场景。

## 4. 人工验收步骤

1. 在Ubuntu干净环境按文档启动并恢复数据，Web核对期初/Artifact/实验，重启后不重复初始化。
2. 从验收中心重跑固定日线与分钟场景，对比Mac净值、订单、费用和研究容差。
3. 验证实际RD-Agent小实验及批准候选仅进入FakeBroker，LIVE与真实券商配置尝试被后端拒绝。
4. 按外部演练步骤重启/断网后恢复，核对在途/UNKNOWN及连续观察；导出三版最终证据并签署。

每次保存testRunId、场景版本、代码/镜像、数据/规则版本、种子及注入事件序列、实际/预期、截图/Trace。判定依据必须是后端事实和独立检查，不能只看Toast成功提示。

## 5. 异常与替身边界

没有Ubuntu实际主机证据不能用M1的AMD64模拟替代最终验收；迁移成功不等于原R2真实实盘通过；未满观察窗口保持NOT_RUN。

### 8.2 初始化与启动（目标命令，待实现）

在上表填写的项目根目录运行；工具版本按锁文件/项目说明准备。首次开发由开发者生成锁文件和脚本，验收者不负责补建环境。环境变量按上表配置；保持FAKE券商与模拟账户，真实模型仅在本阶段明确要求且预算已配置的场景调用。

```bash
# 终端A：先确认实际执行目录为项目根目录
pwd
pnpm install --frozen-lockfile
pnpm stack:up -- --stage V3.4

# 终端B：同一项目根目录，保持开发服务器运行

```

预期：安装与stack入口退出0；stack输出本阶段服务、端口、健康/迁移及持久卷状态。依赖不可用应非零并说明原因；不能删除旧业务卷重试。Web服务器持续运行并输出基础URL，尚在运行不要求退出码0。若已使用容器化Web，则填写已验证入口并避免重复占用端口。Ubuntu部署必须补齐实际镜像拉取/启动/迁移命令，不能仅用dev:web代替发布验证。

### 8.4 命令行复验与相同运行核对（待实现）

在项目根目录执行以下目标命令。stage/scenario必须匹配8.3定义；CLI与Web共用场景版本、Fixture和断言。每条命令执行后立即查看退出码，任何非零先保存错误再定位，不能继续假定本阶段通过。

```bash
pnpm verify:stage -- --stage V3.4 --scenario normal --seed 20260907
# 紧接上一命令执行；0表示全部场景断言通过
 echo $?
pnpm verify:stage -- --stage V3.4 --scenario rejection --seed 20260907
 echo $?
pnpm verify:stage -- --stage V3.4 --scenario recovery --seed 20260907
 echo $?
pnpm verify:stage -- --stage V3.4 --suite code
 echo $?
pnpm test:e2e -- --stage V3.4
 echo $?
```

预期：各场景输出testRunId、实际数据/模型/券商模式、断言expected/actual及证据位置；预期内拒绝场景验证成功退出0，意外副作用/缺脚本/缺必需依赖/未满观察条件非零。恢复场景需外部动作时输出已核实目标和步骤，停留WAITING；完成动作后复验原run，不伪称Web可重启宿主。浏览器测试必须实际运行本阶段用例，零用例/全跳过不能退出0。

再对Web中已运行的同一testRunId执行只读核对，避免仅创建新样本掩盖页面问题：

```bash
# 粘贴Web运行详情中的实际testRunId，再按回车；这是普通ID，不是凭证
read -r acceptance_run_id
pnpm verify:stage -- --stage V3.4 --run "$acceptance_run_id" --check-only
 echo $?
pnpm evidence:export -- --run "$acceptance_run_id"
 echo $?
```

check-only仅查询此运行后端事实并追加检查证据，不创建新订单、不重放成交或发起模型调用；空ID/错误stage/越权run必须拒绝。导出只含脱敏数据，输出实际目录和Manifest Hash，不自动勾选人工验收。端到端正常/异常/恢复运行产生不同ID，导出时分别保存。

本阶段代码测试覆盖要求：Ubuntu真实镜像/迁移/恢复/模型烟测、全阶段浏览器与领域E2E、架构数值比较、连续Paper观察。 在交付时把映射到的实际Domain/DB/契约/服务内测试命令补入本节，注明执行目录、测试文件或套件、退出码和报告；verify:stage必须展示实际调用的测试清单，不能空壳返回0。Python服务使用自身锁定环境，不串用其他服务虚拟环境。

### 8.5 交叉核对、失败定位与恢复

交叉核对：Mac/Ubuntu环境与镜像/数据Manifest、资金/净值/研究容差、恢复证据、各阶段人工签署和观察日期逐项对照。

先检查Web与CLI的testRunId、输入/策略/代码版本和模式是否一致，再按Trace查平台、领域、适配器与持久化证据。页面错误而CLI正确，记录Web失败；二者都错则保留领域断言失败。缺能力先查健康/迁移/数据与日志，不修改余额或订单状态使断言通过。

独立复跑创建新run；测试幂等/检查点/重启恢复则使用原run和原幂等键。故障发生后保留旧证据，修复后新增运行或检查记录；不得清空账本、随机更换seed直到通过。真实观察窗口、来源验证和实际模型调用与加速/录制测试分别记录。
