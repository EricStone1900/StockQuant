## 2. 数据集与前置条件

- 至少CN/US两个市场、两个账户、CNY/USD两币种；覆盖一个账户多策略共享资源、相同ticker、更名和板块差异。
- 固定正常日/中国午休/美国夏令时切换/提前收盘/两国不一致假日，以及单独结算日历。
- 行情包含原价、复权、bid/ask、停牌/未知、缺失、过期与未来可见；公司行动包含拆股、股息应计/到账和费用更正。
- 策略输出包含HOLD、调仓、风险减仓、超预算、证据不足；Mandate有有效、过期、撤销和不匹配版本。
- Paper场景包括全成、部分、拒绝、撤单中成交、UNKNOWN、回报重复/乱序、累计转增量与历史更正。
- 数值Fixture示例：原币现金10000、买入100股、单价10、测试费5，确认后现金8995、100股。费用仅测试值，分别按对应市场规则Fixture决定交易是否合法。
- 真数据库测试使用隔离库/Schema，Artifact与模拟账户独立命名空间；只清理本轮资源，不能清理真实账户数据。
- 真实券商写测试不混入默认CI、安装和初始化命令；必须有本人启用的具体账户、限额、策略、时段与有效Mandate。

## 3. 分层要求

VT01在本轮14个阶段还需检查手册第7/8节：实际前置/命令/URL/固定输入已填写，开发待办有证据；normal/rejection/recovery、code套件、浏览器E2E与Web同run只读核对有报告。命令参数和0/1/2退出码按共同规则第10节。验证“只受理任务/零用例/缺依赖/未满观察”不会报PASS，脚本不能勾选用户人工结论。

| 层级 | 主要验证 |
|---|---|
| Domain | Decimal、日历、PIT、状态机、规则、计数、现金结算、Hash |
| Application | 权限、幂等、事务、依赖失败、Saga与模式分支 |
| 数据库集成 | 真事务/锁/唯一约束、租约、恢复与Outbox/Inbox |
| API/事件契约 | 生成Client、Schema、错误、版本、乱序/迟到/重复 |
| 组件/Web | 两市场页面、自动资格、人工例外、金额/时区、空/错/陈旧状态 |
| E2E | 数据→策略→风控→自动授权→执行→入账→结算/对账，无逐笔人工 |
| 非功能 | 沙箱、暂停/发送竞态、双Worker、断线、灾备、时钟、性能与通知 |

## 5. 人工复核自动流程的步骤

1. 在隔离环境建立CN/US账户与固定输入，重复初始化、重启，核对期初只产生一次。
2. 查看每市场日历、币种、结算与策略版本；分别验证HOLD、拒绝和再平衡结果。
3. 启用PAPER+AUTO_POLICY，批准一次完整Mandate后关闭网页；模拟时钟触发两个市场各自交易窗口。
4. 重新打开页面确认没有逐笔人工批准，批次/订单/Fill/现金/对账/Outcome全部可追溯。固定合法数值案例核对现金8995、100股和费用5。
5. 改用MANUAL_APPROVAL验证批准/拒绝/修改/刷新；非法action、过期、旧版本和不匹配Mandate分别拒绝。
6. 双击、重复事件、同键异载荷、并发策略占用，确认只有一次副作用且不超支/超卖。
7. 制造接受响应丢失、暂停竞态、两Worker竞争和Gateway重启，确认UNKNOWN不重发，暂停前在途请求状态可查。
8. 美股夏令时/提前收盘与中国假日场景回放，确认两个市场不互相误日切；USD不足不能用CNY净值放行。
9. 制造外部订单、公司行动、费用更正和未结算款，核对账户事实、归因与对账阻塞。
10. 验证夜间断网/会话到期/通知失败，恢复后先同步和对账，错过窗口的旧信号不补下。
11. R1对真实数据和只读账户执行以上适用步骤；R2只在本人批准的账户/资金范围进行实际通道验证，记录每市场独立报告。
12. 隔离恢复数据库与Artifact，先暂停；核对券商缺失记录并重建投影，确认不会恢复出重复订单。
