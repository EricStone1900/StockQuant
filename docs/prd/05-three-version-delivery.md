# 本轮三版开发总则与共同验收规则

日期：2026-09-07。状态：计划；没有已实现服务或已通过业务测试。

## 1. 本轮范围与优先级

本文件和三个版本文件夹落实本轮用户要求。本轮开发顺序、券商范围、采样频率、Web验收和发布门禁以这些文件为准；原PRD的领域规则、事实所有权、正确性约束继续适用。原R0～R3是长期产品目标，V1～V3是本轮开发版本，两者不等价。

| 版本 | 交付目标 | 阶段数 | 原计划对应 |
|---|---|---|---|
| [V1 小数据本地模拟闭环](./v1-local-simulation/README.md) | 真实Qlib、小数据、双市场Fixture、FakeBroker、Web与验收中心、日线回测和恢复 | 5 | D0～D4/R0方向；提前RD-Agent环境探针 |
| [V2 免费数据与分钟回放](./v2-data-and-replay/README.md) | A股真实来源/用户历史数据、新闻、≤100在线池、分钟回放、连续Paper与扩容 | 5 | D5数据/模拟子集，新增历史分钟回放 |
| [V3 自动研究与Ubuntu交付](./v3-research-and-ubuntu/README.md) | 真实RD-Agent小实验、独立复算、人工晋升、研究扩容、Ubuntu模拟发布 | 4 | D7研究子集及部署强化 |

三版均不接真实券商，包括只读同步、券商提供的模拟账户API和真实下单。所有券商操作由自有FakeBroker完成，所有订单/资产/成交为隔离模拟事实。后端对真实券商配置和LIVE写操作失败关闭，默认安装、测试、初始化、发布检查无真实订单能力。

A股是本轮真实数据及主要人工验收路径；美股从V1保留市场/币种/时区、结算与完整Fixture闭环。未接入美股真实数据时明确NOT_RUN，不缩减长期双市场目标也不宣称其真实数据验收完成。

六角色Agent、Memory自动学习、复杂Ensemble、完整市场状态策略、财务PIT来源扩展及真实券商/LIVE不属于本轮必交，相关长期需求保留。新闻本轮完成采集/去重/关联/修订/展示，模型事件分析及自动风险动作需后续单独开发或明确启用验收。RD-Agent的研究闭环本轮纳入V3必交，V1/V2核心不依赖它。

## 2. 阶段交付原则

每阶段交付可操作纵向功能：契约与数据→真实后端最小用例→正式Web页面→验收中心正常/异常场景→自动检查→人工签署。服务内部仍按S0～S6推进；V编号不替代领域服务生命周期，也不凭阶段数量计算产品完成率。

允许先Fake外部输入与未来依赖，必须在页面及证据中点名。阶段宣称真实Qlib、RD-Agent、数据库、NATS或Temporal通过时，对应组件必须真正执行。研究小样本证明流程与规则，不证明投资收益或全量容量。

每阶段退出条件：任务完成、Web可操作、业务不变量与恢复适用项PASS、证据可重读、人工签署及限制清单。只有执行完成Toast、空页面、纯JSON或Fixture动画不满足Web验收。

## 3. Web开发验收中心

正式页面按阶段增量建设；长期保留统一入口`/acceptance`，按V1/V2/V3和阶段导航，提供场景目录、参数、预期说明、运行、任务详情、证据、历史对比及人工签署。目标代码位置为`apps/web`、`platform-api-service`和`tests`，无需新增独立测试平台服务。

平台API拥有测试目录/TestRun/人工验收元数据，调用领域命令并汇集只读证据；业务状态、账本、订单仍归原服务。测试服务身份仅能访问本轮隔离账户/namespace，不能跨库修改事实。场景初始化通过授权业务API，故障在数据/券商适配器边界或限定故障点注入。

最小契约（待生成Schema）：

- `TestScenario`：scenarioId/version、versionId/stageId、参数Schema、FixtureRef、requiredCapabilities、可执行步骤、独立断言、人工步骤、风险/清理范围。
- `TestRun`：testRunId、scenarioVersion、market/account/namespace、输入与配置Hash、seed、faultPlan/实际故障序列、clockMode、数据/模型/券商模式、业务runId/Trace、开始结束时间及产物引用。
- `TestAssertion`：断言版本、expected/actual/tolerance、证据来源、NOT_RUN/PASS/FAIL。断言从账本等后端事实验证，不重复读取一个success布尔值。
- `AcceptanceRecord`：运行/阶段/代码版本、人工结论、限制、签署者/时间及证据引用；追加新记录，不覆盖历史结论。

执行状态`QUEUED/RUNNING/WAITING/CANCELLING/COMPLETED/FAILED/CANCELLED`、自动检查结果、人工验收结论分开。等待真实观察日数或外部配置显示WAITING与未完成条件，不能自动标PASS。

目标接口：场景列表/详情、创建TestRun（202）、查询/取消、追加人工结论、下载证据。写接口具备认证、作用域、Idempotency-Key、版本冲突及审计。正式业务页面和验收中心复用组件/API，不重复实现规则。

任务由后台执行，页面轮询或事件订阅仅展示；关闭/刷新后按testRunId恢复。取消研究、停止回放和暂停新订单语义分开，合法在途成交继续入账。验收页至少包含加载、空、错误、403、陈旧、部分成功、版本冲突状态和易读金额/本地时间。

每运行独立账户/namespace/Artifact前缀；重新运行生成新testRunId。清理必须展示具体目标、拒绝活动运行及范围外资源，默认保留历史证据；Web不得提供任意SQL/shell、全库重置或宿主Docker管理入口。基础设施故障由脚本/人工执行，页面指导并汇集恢复证据。

## 4. 模拟券商与可复现故障

FakeBroker持久化自己的订单、成交和资产状态，通过协议向执行服务报告；不能直接用内部组合快照充当独立券商对账数据。测试费/初始资金/价格必须标Fixture，例如10000现金、100股×10、费用5→8995现金，仅作为手算案例。

先提供可选择的固定场景，再加入有seed的概率故障。保存故障计划和实际发生顺序；重放序列比单独seed更可靠，尤其存在并发时。正常成交由策略订单与撮合模型决定，不随机制造股票/价格/利润。协议破坏样本另标无效回报，验证隔离处理。

固定场景至少包括拒单、部分成交、撤单期间成交、撤单拒绝、接受响应丢失、查询暂不可用、重复/乱序/迟到回报、累计转增量、费用更正及模拟外部订单。UNKNOWN不是失败，不能盲目重发、按TTL释放资金或把取消点击当撤单确认。

## 5. Mac M1、Docker与Ubuntu

日常优先Linux ARM64容器；依赖/镜像确证后再标支持。Qlib与RD-Agent分别固定源码commit及Python/数值库/构建工具锁，开发可挂源码editable安装，编译扩展/虚拟环境留在Linux容器内。生产镜像使用固定构建产物，不把Mac的`.venv`或`.so`搬入Ubuntu。

Web可原生开发热更新，验收使用实际容器后端，并补一次容器化Web构建/运行。Compose按`core/data/research`配置按需启动；数据库可一实例多领域库；默认研究并发1，设置CPU/内存/磁盘配额，记录本机实际资源后冻结各阶段性能预算。

Qlib和RD-Agent依赖不必共用Python环境；RD-Agent控制器与Qlib实验镜像分离，并在同一固定样本上证明所用Qlib fork一致。生成代码容器无宿主Socket和秘密；可信控制器与研究执行环境的权限及路径映射需独立验证，Socket只读挂载不等于受限Docker API。

V1先做RD-Agent环境/固定代码实验探针；缺LLM凭证不伪称完整实验。V3必须实际模型调用与生成代码执行，模型调用费用单独预算，免费行情不等于LLM免费。

目标Ubuntu若为x86则构建/烟测linux/amd64；M1模拟AMD64只作小样本兼容验证。若ARM64依赖不支持，记录失败再采用AMD64模拟或远程Ubuntu开发。V1/V2至少尝试目标架构烟测并登记缺口；V3必须有真实Ubuntu部署/恢复/E2E证据。不能承诺所有上游场景原生支持M1。

named volume和Artifact需显式备份/恢复。镜像迁移不自动迁移数据，模型/数据还需校验Hash、权限和挂载路径。每次报告hostArchitecture、containerPlatform与emulated，区分Mac本机、模拟架构和真实Ubuntu。

## 6. 小数据、免费来源和采样

先用固定样本验证手算/异常，再用少量真实数据走实际Adapter。日线至少覆盖因子预热，模型另满足训练/验证/测试与标签窗口；短历史返回明确不足。历史回测保留当时证券范围及退市样本，不能用今日在线池替代历史股票池。

在线监控去重后≤100只，持仓与在途证券最高优先；超过上限阻塞配置并提示处理，不静默漏掉持仓。优先使用支持股票过滤/批量的来源，不支持则限速分批；数据源只提供全市场接口时不能宣称满足限定股票请求，须记录限制并选择其他Adapter。

默认交易时段30分钟采样、可配置20分钟，替代本轮的原10分钟研究采样默认。评估间隔不得小于实际证据覆盖并假装获得新信息；更快评估可复用旧窗口但标明年龄/未更新。每日收盘确认日线、盘中快照采样、策略评估、下单窗口相互独立，不保证每周期有交易。

免费来源先核实许可/认证/限流/延迟/历史覆盖，再选型；适配层保存来源、原始证据、版本和适用时间戳。新闻至少两个经验证来源用于聚合，去重/转载/修订与实体歧义可查；非授权正文不强行留存。缺源时可用Fixture开发，但实际来源验收仍NOT_RUN。

快照数据不重建不存在的分钟OHLCV，不把盘中累计量直接当某分钟成交量。`SNAPSHOT`、`DAILY_BAR`、`MINUTE_BAR`报告分开；分钟数据可由用户文件提供，不以找到完整免费历史分钟源作为前提。

## 7. 历史回放边界

V1预留按run隔离的Clock和执行端口，V2实现MinuteBar、ReplayManifest、检查点和HistoricalReplayRunner。Clock贯通策略、风控有效期、授权、订单、结算与绩效；领域禁止自行读取壁钟。基础设施网络超时仍用实际单调时钟，不随历史时间加速。

编排服务拥有调度/工作流，量化服务拥有回测Manifest/计算运行/报告，执行服务拥有历史撮合适配器/订单，组合服务拥有模拟账户/账本。Web/TestRun只是触发和证据索引。历史行情在Worker按分区推进，Temporal只记录粗粒度工作/检查点；不把每根Bar写成工作流Activity。

每个历史时刻有确定性事件排序和完成屏障，待本步业务副作用处理完才推进。检查点包含行情游标、种子/事件、虚拟时钟和业务版本，恢复用原幂等键，不创建第二笔成交。运行namespace同时约束订单、账本、缓存和事件。

MinuteBar需明确barStart/barEnd/availableAt和RAW价格/量额单位。完整Bar在结束后才可用于决策，窗口VWAP不可在窗口开始预知。限价触价、参与率和成交量基于明确假设；未知队列/Bar内路径采用保守模型，结果不能当交易所级复现。未来LIVE报价政策不因允许快照模拟而放宽。

Qlib快速研究与全链路回放分别标注执行模型。复用确定性规则而非复制；若为性能引入领域库快路径，必须有通过真实服务的小样本对照。每日信号最早下一可交易时点撮合，盘中风险动作仅在已授权策略范围，默认不增加Alpha交易。

## 9. 持续观察和完成定义

V2目标A股20个实际交易日连续Paper观察，V3迁移后Ubuntu至少5个实际A股交易日且含日终。每阶段可通过加速Fixture即时验证功能，实际观察证据单独累计；独立下一阶段可继续开发，不能提前签署观察门禁。

Mac睡眠/断网和源失败须如实留痕，不删窗口改善可用率；观察期内硬正确性失败需修复、重验并追加观察证据。Ubuntu目标资源/性能预算先记录后测，未确认或未达标项保持未完成。

本轮最终交付为三版研究与模拟交易平台、可保留的Web验收中心、实际Ubuntu模拟部署及证据。原真实券商、真实账户、R2实盘和未纳入增强功能单独列后续，不以三版PASS覆盖原长期验收。

## 10. 阶段待办与可执行验收手册

每份阶段文件第7节维护交付复选框，第8节包含验收前提、环境/数据填写表、启动命令、Web正常/异常/恢复步骤、代码与CLI测试、同run核对、预期结果、故障定位及签署表。详细开发任务仍保留第2节，版本99-acceptance汇总最终结果。

手册当前为`DRAFT_NOT_EXECUTABLE`，说明命令/场景/URL尚为契约。开发者须实现入口、补全实际参数和测试命令、冻结Fixture与预期、从头执行并保存证据，才改为`VERIFIED_EXECUTABLE`。这个状态只表示操作说明实测可执行；自动断言和用户人工验收仍各自保持NOT_RUN/PASS/FAIL，不能自动联动勾选。

交付时不得保留影响执行的“待实现后填写”：必须给出项目目录、工具版本、Web实际地址/登录方式、按钮/路由、Fixture具体文件或数据版本/日期/Hash、配置变量名和非秘密值、故障目标及恢复命令、预计耗时和轮询超时、测试文件/套件与实测输出。凭证只说明安全配置渠道，不贴真实值。新增操作改变代码/场景版本时重新核验受影响手册。

下列参数扩展同第8节已有入口合并实现，不新增另一套测试运行机制：

| 目标命令（待实现） | 固定语义 |
|---|---|
| `pnpm stack:up -- --stage V1.3` | 根据版本化阶段能力清单启动所需服务/迁移，打印实际端口与健康；同目标幂等，不删卷，不调用模型 |
| `pnpm verify:stage -- --stage V1.3 --scenario normal --seed 20260907` | 创建隔离run、按场景准备数据并验证正常流程；生成代码/实际来源仅在阶段声明的场景使用，记录模式和预算 |
| `pnpm verify:stage -- --stage V1.3 --scenario rejection --seed 20260907` | 执行该阶段表中全部拒绝子场景，各自隔离并提供逐项断言 |
| `pnpm verify:stage -- --stage V1.3 --scenario recovery --seed 20260907` | 执行重复/恢复子场景；外部故障仅限经核实的测试目标，需人工时等待并显示具体步骤，不无限挂起或默认通过 |
| `pnpm verify:stage -- --stage V1.3 --suite code` | 从阶段清单调用实际lint/typecheck/Domain/DB/契约等适用检查，输出具体命令/工作目录/测试文件、退出码和报告；不能只校验场景JSON |
| `pnpm verify:stage -- --stage V1.3 --run RUN_ID --check-only` | 只读已有run业务事实并保存新断言证据；不重新初始化、不重放事件、不下单、不调用模型；验证stage/所有者匹配 |
| `pnpm test:e2e -- --stage V1.3` | 实际执行本阶段正常/异常/恢复适用浏览器用例，零用例或全部跳过不得成功 |
| `pnpm evidence:export -- --run RUN_ID` | 导出此run的脱敏证据及Manifest Hash，保持人工结论不变 |

normal/rejection/recovery是每阶段场景入口，唯一键为stage+scenario+scenarioVersion。实际场景可含多个子用例，报告逐项列出，不能以一个子项通过覆盖其他项。CLI/Web复用定义与独立断言，不能只因两者success字段相等而判通过。

场景与code/browser命令的退出码：0=所有适用检查PASS，1=断言/代码/执行失败，2=尚未完成或缺必需前置（含实际观察WAITING），非法参数可另用明确非零码。适配底层命令时同时保存其原退出码。启动/导出入口0仅代表该操作成功，不代表阶段验收；dev:web为持续进程，不要求启动后立即退出0。

长任务受理输出runId不代表通过；在有界等待后尚未完成时退出2并输出重新查询同run的命令。check-only可以在外部步骤完成后验证原run，但不会代为恢复业务任务；恢复动作必须在场景/手册内写明并操作，再检查结果。所有超时/取消/缺测试脚本必须返回非成功状态。

每阶段`--suite code`清单需映射到具体实现。例如已配置的Python服务在自身目录执行`uv sync --frozen`、`uv run ruff check .`、`uv run mypy src`、`uv run pytest tests/unit`及该阶段实际DB/契约测试；TS对应实际pnpm质量/类型/测试入口。测试文件/标记和服务工作目录在阶段交付时列出，未创建目录/脚本不能凭模板宣称已跑。只读核对与证据导出不重新产生付费模型调用。
