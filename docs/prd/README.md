## 如何开始新项目

1. 把整个`product-rebuild`目录复制到一个空项目，例如放到`docs/product-rebuild/`，无需携带其他项目文件。
2. 阅读[产品PRD](./00-product-requirements.md)，确认默认证券范围和第10章中的券商、部署、资金、数据等参数。
3. 按[架构设计](./02-system-architecture.md)与[双市场契约](./03-market-rules-and-contracts.md)冻结新项目S0，创建生成Schema和核心服务骨架。
4. 本轮按[三版共同规则](./05-three-version-delivery.md)从V1.1推进，逐阶段读取文件夹内任务；[原实施计划](./04-development-plan.md)的D0～D7保留为来源映射。
5. 按各版90-test-plan与99-acceptance执行Web和自动检查，保存人工签署；[总验收](./99-acceptance.md)分别记录本轮V1～V3与长期R0～R3，不用模拟通过替代实盘。

## 本包边界

本包为全新项目设计，没有预置代码、脚本、数据库或已完成阶段。代码路径和命令都是待创建产物；所有内部文档链接都在本目录内。官方公开规则链接仅作上线核验参考，不是其他项目依赖。

量化自动执行是必需能力；Agent、自动研究和学习为可选增强，QUANT_ONLY可独立达到主要目标。正式默认采用现金多头、常规时段和按市场白名单；券商、资金、风险阈值和主机由本人确认，不在文档中伪造配置。

## 建议交给新项目开发者的任务说明

> 根据本目录05-three-version-delivery和三个版本文件夹，从V1.1逐阶段开发本轮研究与模拟平台。每阶段同步正式Web、开发验收中心、正常/异常测试及人工证据；先小数据真实Qlib，后免费行情/新闻、分钟回放、真实RD-Agent实验及Ubuntu迁移。全程自有FakeBroker与模拟订单，不接真实券商。遵守原架构所有权与服务S0～S6，不假定代码/脚本已存在；未跑保持NOT_RUN。长期实盘和未纳入增强需求另行推进。
